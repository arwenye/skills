# Experiment Notes Skill

实验结束后调用，把本次实验的核心学习沉淀成笔记文件。

---

## 准备工作

生成笔记前，依次读取：

1. **实验规划**（如果存在）：`docs/notes/[章节]-[实验名]-plan.md`，获取出发点、设计决策、思考题。
2. **实验 README**：实验目录的中文 `README.md`，补充背景。
3. **值得读的代码**：从实验规划的代码阅读清单中，只读被标记为"值得读"的函数/行范围。如果没有规划，只读：
   - 核心数据结构定义（主类的 `__init__` 或 `@dataclass`）
   - 主循环或核心处理函数
   - 评分/判断逻辑（如果有 benchmark）

---

## 询问用户

读完材料后，向用户确认（没有的跳过）：

1. **实验观察**：运行过程中有什么不符合预期的输出，或者让你停下来想了一会的现象？
2. **遇到的 bug**：修复过什么问题，根因是什么？
3. **检验题**：实验规划里的思考题，哪几个最有收获？

用户的回答直接写入笔记，保留原始观察的具体性。

---

## 笔记结构

**固定章节（每份笔记都有）：**

```markdown
# [章节编号] · [实验名] 实验笔记

> 实验路径：`[实验目录]`  
> 对应书中：[实验编号和名称]

---

## 实验出发点

[一段话：这个实验解决什么问题，从什么现象或痛点出发。不写"学习 X"，写"X 场景下 Y 会出什么问题"]

---

## 知识地图

[用缩进列表展示核心概念的结构关系，3-5 个节点]

---

## 架构

[ASCII 流程图，标注核心组件和数据流向]

---

## 核心机制

[只写"值得读"的代码。每个模块一个小节：
- 函数名 + 文件:行号
- 一句话说它做什么
- 核心代码片段（不超过 15 行）
- 关键点：为什么这样写，有什么限制]

---

## 实验观察

[直接记录跑出来的现象，不符合预期的结果。
格式：现象 → 根因 → 结论]

---

## 检验题回答

[按机制层 / 设计层 / 工程层分组，每题一段，回答具体可验证]

---

## 个人项目参考

[沉淀可复用的结论，格式：
- **[模式名]**：[一句话描述这个模式] → [适用场景] → [注意事项]
这里写的是判断和经验，不是复制代码]
```

**按需章节（有内容才写）：**

| 章节 | 什么时候加 |
|------|-----------|
| `## [A] vs [B] 核心差异` | 实验本身是横向对比 |
| `## Benchmark 评分分析` | 评分器有值得记录的问题 |
| `## Bug 修复记录` | 修复过非 trivial 的 bug |
| `## 未解决的问题` | 实验结束后仍有疑问 |

---

## 写作规范

**代码引用：** `` `函数名()` ``（`文件名.py` 第 N 行）

**架构图：**
```
组件A
    ↓ 操作名
组件B
    ├── 子组件1  — 说明
    └── 子组件2  — 说明
```

**Bug 记录：**
```
根因（文件名 第 N 行）：一句话说根因

修复前 → 修复后（代码片段）
```

**不写的内容：**
- 不解释 Python 语法或基础概念
- 不重复 README 里已有的内容
- 不写"通过本次实验我们学到了……"这类收尾语

---

## 保存

文件名：`[章节号]-[实验名].md`，保存到 `docs/notes/`。

如果文件已存在（从实验规划生成过），**更新**而不是新建，把"实验观察"和"检验题回答"填入预留位置。

保存后告知文件路径，以及下一个相关实验是什么（如果能从章节结构推断）。
