# Experiment Notes Skill

实验结束后调用。核心原则：**笔记深度匹配规划量级；顶部放最重要的东西，细节往下沉。**

---

## 前提：这份笔记给谁看

- **未来的自己（回顾）**：5 分钟内重新进入实验，不用重跑
- **外部读者（输出）**：不了解实验背景的人，能在 2 分钟内理解价值和限制

这两种需求对应笔记的两个层次：
- **顶部**：核心发现 + 可分享摘要（给任何人看）
- **底部**：检验题回答 + 深度机制（给重新上手的自己看）

---

## Step 0 — 确认量级与已有文件

1. 检查是否有规划文件 `docs/notes/[章节]-[实验名]-plan.md`
2. 读规划里的"掌握深度"表（L3）或"核心假设"（L2）——这决定笔记的深度
3. 读 `validation/latest.json` 或实验产出里的关键数字
4. 量级匹配：L1 规划 → L1 笔记；L2 → L2；L3 → L3。**不要对 L1/L2 实验做 L3 的全量记录**

---

## Step 1 — 向用户确认三件事

读完材料后，只问这三个问题（有答案就填，没有就跳过）：

1. **预测对照**（L3 专用）：规划里的事前判断，哪条预测错得最多？原因是什么？
2. **最有收获的检验题**：哪一条思考题花的时间最多、或者答案最出乎意料？
3. **不符合预期的现象**：有没有哪个数字 / 行为跟你预想的不一样？

---

## Step 3 — 写作规范

**核心发现和可分享摘要**：
- 写给没跑过实验的人，不用实验里的缩写
- 结论要包含前提：不是"前缀有效"，是"在块内缺主题词时，前缀改善 top-1 召回"
- 限制必须说：没有限制的结论是不完整的结论

**检验题回答**：
- 用数字说话：`+20pp`，不是"提升很多"
- 写 `[掌握]` 层；对 `[理解]` 层只写一句结论；`[委托]` 层直接跳过
- 答案里出现"这说明"之前，先确认你有能支撑它的证据

**个人应用**：
- 格式：在什么条件下 → 用什么 → 注意什么
- 不写"值得借鉴"、"可以参考"、"有启发"
- 不写"下次可以尝试"——那是未来的任务，不是当前的总结

**禁止**：
- 把代码块大段搬进笔记（代码在源文件里，笔记讲的是机制）
- 重复 README 里已有的内容
- 结尾写"通过本次实验学到了……"

---

## Step 4 — 写入文件

**始终新建文件**：`docs/notes/[章节]-[实验名].md`，不更新、不合并规划文件。

规划文件（`-plan.md`）记录"进去之前想的"，笔记文件（无后缀）记录"出来之后知道的"——两份文件并存，分开看。

写完告知文件路径。如有未解决问题，提示："这里有 X 条未解决的问题，下次规划时可以作为事前判断的候选。"
