# Experiment Plan Skill

用于**进入新实验前**生成一份规划。核心规则：**规划深度匹配实验重要性**，不要对所有实验用同一套模板。

---

## 前提：这个 skill 在训练什么

三种能力，其余都是副产品：
- **理解力** — 看懂 AI 产出的每个数字是怎么来的，才能做 evaluation
- **判断力（taste）** — 两个都能跑通的方案选哪个；0.006 的差距算不算差异
- **泛化** — 假设换语料、换规模、换指标，哪个先失效

### 复现是个连续谱

```
跑通代码  →  复现数值  →  理解实现  →  从零实现  →  在新场景验证
         L1          L1-L2          L2-L3           L3
```

目标：**你掌握设计边界，agent 执行实现细节**。
深度判断：要改 / 设边界 → `[掌握]`；要预测行为 → `[理解]`；只用接口 → `[委托]`

### 三条硬规则

1. **只写"看哪里"，不写"结论"。** 出现"这说明……"就是把思考替用户做完了，规划作废。
2. **数字分两类。** `[校验]` 确认你读对了文件；`[待测]` 要用户自己算，绝不能给。
3. **审查题要在看见产出之前写好。** 事后写的标准不是标准，是理由。

---

## Step 0 — 先估量级

读完 README 后，先判断这个实验值多少投入，再决定输出哪种规划。

| 量级 | 判断依据 | 输出形式 | 时间预算 |
|------|---------|---------|---------|
| **L1 扫一眼** | 工具 / 基础设施；你不打算改它，只用接口 | 一段话（做什么、怎么调、主要限制） | ≤15 分钟 |
| **L2 轻量规划** | 技巧 / 组件；理解原理就够，不深改 | 旧方案 + 假设 + 2-3 步 + 1 条思考题 | 30-60 分钟 |
| **L3 完整规划** | 核心方法；你要在此基础上设计 / 评测 / 改进 | 完整规划（含掌握深度、事前判断、三档思考题） | 2-4 小时 |

**L1 / L2 不套 L3 的模板** — 把轻量实验拍成完整规划，是本 skill 要防的另一种退化。

---

## Step 1 — 读实验材料

1. 实验目录 `README.md`——理解"解决什么问题"
2. 入口文件 import / 类名——只读顶部 20 行
3. L3 专用：`validation/latest.json`、`evidence.json`——找一个真实可判定的缺陷候选，供审查题使用；**找到后不要说出结论，只指向位置**

## Step 3 — 代码阅读清单判断标准

| 深度 | 值得读的位置 |
|------|------------|
| `[掌握]` | 评分/判定函数；不显然的 if/else；失效条件触发处 |
| `[理解]` | 核心数据结构；主循环的退出条件 |
| `[委托]` | 框架内部、retry、序列化、CLI、日志——直接写进"跳过" |

读代码表里不要写结论，写"这里决定了 `x` 怎么算"。

---

## Step 4 — 写入文件

- L1 → 直接追加到 `docs/notes/[章节]-overview.md` 或 inline 回复
- L2 → `docs/notes/[章节]-[实验名]-plan.md`
- L3 → `docs/notes/[章节]-[实验名]-plan.md`

写完提示用户：先填"事前判断"，再跑第一条命令；实验结束后用 `/experiment-notes` 补充观察。

---

## 输出要求

- L1 正文 ≤ 10 行；L2 正文 ≤ 30 行；L3 正文 ≤ 80 行（不含表格）
- 命令必须可直接复制；跑不通的前提写在步骤表上方
- 禁止：`这说明` / `其实是因为` / `所以结论是`
- 数字必须标注 `[校验]` 或 `[待测]`
- L3 代码阅读清单每项必须标注 `[掌握]` 或 `[理解]`
- L3 必须齐：1 条审查题、1 条判断题、1 条迁移题、1 条指标可信度类失败模式
